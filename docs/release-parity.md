# Release and Google Play distribution

Both distribution channels build the same release variant from the same tag, with
the same catalog, features, and native libraries. Package: `com.loxifi.kairodos`.
The first synchronized release is `v0.9.0`, versionCode `900`; Kairo98 previously
published `v0.8.0`. Version codes follow major * 1000000 + minor * 100 + patch.

The tag workflow builds `:kairodos:assembleRelease :kairodos:bundleRelease`,
verifies signatures, package ID, version, release mode, ARM64 ELF alignment and
matching payloads, then publishes the APK and Play AAB. Release assets use
`catalog/online-v1.zip`, generated by `tools/BuildPublicDosCatalog.ps1`, without
the private description fields or bundled game artwork. Debug assets are retained
for local development. Release output is not silently signed with a debug key.

## Signing continuity

The existing persistent Kairo key signs both products. Certificate SHA-256:
`C321EC6B35E2509741362FCC3FEDE816C81510AA8133D791EA55CE0E1594A51C`.
The certificate's historical alias/name contains "beta"; it is a persistent
release identity, not Android's debug key. Local ignored key/password locations
and environment variable names are recorded in `AGENTS.md`.

Existing DOS development installations use a different debug certificate.
Android cannot replace them with this release APK. Preserve app data and do not
uninstall or change package IDs merely to bypass the signature mismatch.

When enrolling in Play App Signing, import the existing app signing key to keep
GitHub/Play update compatibility. A Google-generated different app signing key
would produce APKs incompatible with direct GitHub updates. An AAB's upload
signature alone does not prove the final Play-delivered APK uses the same key.
After enrollment verify the app signing certificate in Play Console against the
fingerprint above. Keep secure backups of the key and password; GitHub secrets
cannot be downloaded as a backup.

## Verification boundaries

The shared artifact audit checks ELF alignment for 16 KB pages and identical
assets/native libraries between APK and AAB. The workflow also runs zipalign.
These are packaging checks, not proof of game execution on a 16 KB Android
system. A 16 KB runtime check, Play Console enrollment, listing declarations,
and the complete license/distribution review remain separate release-readiness
work. Do not infer Play approval from a successful tag build.

References: [Play App Signing](https://developer.android.com/studio/publish/app-signing),
[16 KB page sizes](https://developer.android.com/guide/practices/page-sizes),
[target API requirements](https://developer.android.com/google/play/requirements/target-sdk).

## Image-inclusive download

From v0.9.1, each tagged release also publishes `KairoDos-<tag>-with-images.apk`.
It includes the bundled artwork and uses the same package, release signer,
version, and non-artwork payload as the smaller APK. CI builds and audits all
three outputs and verifies both APK signatures. The Play AAB remains the
variant without bundled artwork.
